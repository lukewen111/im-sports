# ChatScale V1.0 PRD 符合度体检（只读）

- 体检对象：`vben-prototype/`（Vue 3 + Vben + Element Plus）主演示版本
- 对照文档：`ChatScale_V1.0_完整产品需求文档_PRD_最终版.md`
- 体检日期：2026-11-04
- 体检方式：静态阅读路由、页面、Pinia Store、Mock 数据；未安装依赖、未运行构建、未修改任何业务代码
- 结论口径：严重度以「能否支撑现场演示」为准，而不是以真实后端完整性为准。Mock 本身不算缺陷，但「设置项存在却没有任何可见效果」「状态流转不可见」「权限范围不生效」算缺口

## 1. 总体结论

| 指标 | 数量 |
| --- | --- |
| P0（核心演示流程走不通或明显穿帮） | 6 |
| P1（影响产品说服力） | 29 |
| P2（细节、文案、边界） | 17 |
| 合计 | 52 |

主演示版本判断：**`vben-prototype/` 是当前主演示版本**。依据是根目录 `ROADMAP.md` 最新记录、`vben-prototype/package.json` 的独立 dev/build/typecheck 脚本，以及业务路由、团队/渠道/聊天/客户/设置/个人中心的完整页面均只在 vben 版存在。根目录 React 工程仅剩渠道管理页和渠道客户端页，作为参考实现保留。

最关键的 8 条：

1. **没有演示身份切换入口**：角色配置改完后，无法在同一浏览器里切到管理员/客服/其他成员验证权限差异。
2. **聊天「全部 / 待分配 / 已结束」没有应用数据范围**：普通客服能看到无权团队的会话，角色数据权限演示会直接穿帮。
3. **会话生命周期系统事件缺失或不一致**：没有「会话开始」「进入待分配」，接管不产生「已分配给 X」，结束文案缺时间；客户侧也没有系统事件。
4. **客户「回聊」固定取渠道列表第一个渠道**，不是客户原咨询渠道；原渠道删除后仍会静默换渠道创建会话，与 PRD 明确相反。
5. **关闭「接受聊天」、退出登录、修改密码都不会改派在接待中的会话**，个人中心的核心联动演示无法闭环。
6. **翻译设置完全空转**：设置页有接收/发送翻译开关，聊天窗口没有任何翻译入口、译文展示或发送预览。
7. **消息通知开关完全空转**：页头闪烁、浏览器通知、提示音均未实现，顶栏通知还是静态假数据。
8. **聊天第四栏信息严重不全**：缺「开始于」、渠道类型、近期会话、访问信息、基础信息编辑、折叠分组；同时 AI 成员/同事两个固定分组缺失。

## 5. 需用户决策的模糊点

以下问题可直接回答「做/不做/按哪个口径」：

1. **AI 成员/同事分组是否本期补齐？** PRD 要求六个固定分组，但当前没有 AI 消息角色、没有 AI 接待会话，也没有同事接待中的 Mock。若不补，是否接受「聊天只演示我的/待分配/全部/已结束」并在评审时说明范围裁剪？
2. **演示身份如何切换？** 是加一个显式的「切换演示身份」入口（顶栏或团队页），还是接受用浏览器多 Profile / 手动改 localStorage？这决定角色配置能否现场验证。
3. **设置归属是否按 PRD 拆？** 会话设置保持租户级，通知/翻译改为成员级；还是本期全部保持租户级、在 PRD 上标注简化？
4. **翻译和通知要做"真效果"还是"演示态"？** 翻译是接真实接口，还是本地静态词表/预置译文？通知是否必须真实触发浏览器 Notification、页头闪烁和提示音？
5. **超时规则是否要可观测？** 2 分钟首次响应、10 分钟自动结束，是否要做真实定时器并可现场等待验证，还是只保留配置、验收时用缩短时间/手动触发演示？
6. **客户详情是否必须右栏联动？** 当前抽屉能承载信息；是否接受用抽屉替代 PRD 的「左右面板」，还是必须改成列表常驻 + 右栏详情？
7. **回聊渠道怎么定？** 严格按客户原咨询渠道（删除则禁止、停用则允许创建但不能发）；还是允许人工在回聊时选择渠道？跨渠道客户以哪条会话为"原渠道"？
8. **客户侧系统事件是否必须做？** Web 客户端是否要展示「已分配给 X / 进入待分配」？这需要打通客户端本地会话与服务端会话，改动比工作台单侧大。
9. **权限收回是否页内强退？** 角色权限被撤销时，是否要求当前打开页面立即弹回/停止操作，还是仅下次导航时生效？PRD 6.11.1 要求前者。
10. **本轮修复范围如何取舍？** 是 P0+P1 全修（35 条），还是只修 P0 与少数 P1 以保演示主线？P2 是否统一延后？

## 6. 风险与改动面

### 6.1 高耦合、会碰共享状态

| 文件/Store | 影响范围 | 风险 |
| --- | --- | --- |
| `features/service/demo-store.ts` | 聊天、客户、设置、个人中心、渠道客户端全部读写 | 会话/消息字段一改就要处理 localStorage `service-demo-v1` 旧数据；建议 bump key 或写迁移。加系统事件、未读按成员、访问信息、等待队列时间、AI 消息角色都在这里 |
| `features/team/team-store.ts` | 成员上下线、删除、团队删除、角色计数 | 改派逻辑需要同时改会话，但 demo-store 已依赖 team-store；team-store 反向 import demo-store 会形成循环依赖。建议把「改派」放在页面层或事件总线/service 层，避免 Store 互相 import |
| `features/team/access-store.ts` + `role-store.ts` | 菜单、路由守卫、数据范围 | 身份切换、权限即时收回会同时影响菜单、路由和聊天数据过滤；角色保存后要触发会话改派 |
| `features/channels/channel-store.ts` | 渠道删除/停用、团队删除迁移 | 删除渠道要结束会话，但 channel-store 不宜直接依赖 demo-store；建议由渠道页调用 service 清理 |
| `layouts/basic.vue` + `bootstrap.ts` + `store/auth.ts` | 顶栏身份、头像昵称、退出登录 | 把顶栏从 Vben `userStore` 改为响应式读取原型成员，会影响登录态和 Vben 默认用户信息；退出登录还要触发离线改派 |

### 6.2 相对纯增量（低风险）

- 聊天分组新增 AI/同事、列表渠道图标/接待人/等待时长、已结束筛选项与排序：主要改 `inbox/app.vue`，新增纯函数过滤即可。
- 第四栏补「开始于/近期会话/访问信息/折叠」：新增会话字段 + 展示，不改既有字段。
- 客户列表操作列补「回聊/去聊天」、详情改右栏：页面结构改动，不动 Store 协议。
- 客户筛选改渠道类型、团队默认全选、日期范围：页面层增量。
- 个人中心下拉菜单补 Switch/语言、团队空值显示「—」、头像校验：入口/表单层增量。
- 设置拆三个二级页面：路由与页面拆分，可复用现有 Store 字段。
- 时间格式统一：抽一个 `formatImTime` 工具，替换聊天/客户/团队时间展示。
- UI 视觉统一：新增 CSS 变量与公共卡片/表格/表单类，主要动样式，不动业务逻辑；但聊天第四栏重排会碰 `inbox/app.vue` 的模板结构，属于中等风险。

### 6.3 会改变数据模型的改动（需先决策再动手）

- 未读从 `unread: number` 改为「按成员读位/未读映射」。
