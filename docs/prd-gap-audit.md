## 自查方法为什么漏报

| 漏报原因 | 具体表现 | 这次如何避免 |
| --- | --- | --- |
| 只对「字段有没有」 | 旧体检按字段清单打勾，没看该字段在哪些分组/状态下才渲染 | 以 PRD 的限定词（仅/不/必须/固定）为检索词，反查 `v-if` 外层条件 |
| 把「页面可见」当「全局可见」 | 搜索筛选只写在已结束，但曾按「是否有搜索框」判为有 | 每个入口追到分组条件 `group === 'ended'` |
| 旧快照 | 11-04 报告与今天代码已大量变化（客户详情、筛选、时间格式） | 只读当前工作区，并标注读取时间点 |
| 例外被过度放大 | 「列表标题只显示接待数」被误当成「左栏分组角标也可以有数字」 | 区分「列表标题右侧」与「左侧分组角标」两个位置 |
| 不追数字来源 | 角标只看渲染结果，没追 `groupCounts` 口径 | 每个数字追到 computed 与 PRD 定义逐项比对 |
| 文案按近似判断 | 「左侧/右侧」被当作「左下角/右下角」同义 | 固定文案逐字 grep，近似即记为差异 |

以后判定清单（按 PRD 章节逐条打勾）：

- §2.1 六个分组的定义与顺序
- §2.2 每个分组是否展示角标、角标口径
- §2.3 数据范围与权限
- §3.1 列表字段逐项
- §3.2 排序键与方向（含唯一性）
- §3.3 搜索筛选入口可见范围
- §3.4 未读归属
- §4.1-4.7 头部、消息、系统事件、输入、接管/转接/结束
- §5.1 翻译四条件
- §5.2-5.5 客户详情字段集合
- §6 团队/角色权限矩阵与 0 成员文案
- §2.1-2.3（渠道）删除、停用、绑定、TG 显示
- 设置三页逐条
- 访客端系统事件渲染范围与渠道差异
- 固定文案逐字、空值 `—`、时长单位、重复提交

每一章三问：**入口在哪些分组可见？数字口径从哪来？文案是否逐字一致？**
